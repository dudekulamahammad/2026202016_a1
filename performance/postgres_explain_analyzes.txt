PERFORMANCE ANALYSIS:
The query processes completed trips and calculates daily revenue,
7-day moving averages, and DENSE_RANK rankings.

The trips table contains approximately 100,001 rows, of which only
2 rows are not COMPLETED. PostgreSQL therefore chose a sequential
scan instead of the partial index idx_trips_status_completed because
the filter is not selective enough for an index scan to be cheaper.

The partial index idx_trips_status_completed exists and can be used
for COMPLETED-trip lookups. A diagnostic EXPLAIN with sequential scans
disabled confirmed that PostgreSQL can use the index.

The sequential scan in the original plan is therefore a cost-based
optimizer decision rather than a missing-index problem.
